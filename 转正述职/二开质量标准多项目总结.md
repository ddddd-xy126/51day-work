- C1 交互时序/互斥缺失 → 搁置：场景状态互斥属项目定制逻辑，各项目需求不同，无统一分级必要，暂不纳入质量清单，互斥关系在需求清单需求描述中说明即可。

- C3 布局还原 → 开发规范/测试反哺：skill 还原间距需 1~4 轮反复验收测试；可先由 AI test 质检识别「高度塌陷压下方区块」等问题反哺修改；master go 插件标注的字号、字重有参考价值，绝对定位间距不具参考性。
- C4 坐标/高度 → 不做（人工 review）：Surface Ground 与高度参数同时标注时高度异常，疑似参数叠加逻辑变更；玉和田专项由萨老师 24 号修复但不覆盖全场景；暂无通用解，纳入人工微调与效果 review 环节，优先保障交付。
- C5 接口契约 → 修改框架：标准未规定接口失败回调提示，开发侧也无抛错设计；参考天津项目实践，一致同意补充规范并下沉到框架，做事件与枚举的映射。
- C6 数据来源 → 开发规范：无接口数据写「-」不写死数据（TB 特殊要求除外）；设计 AI 维护项目排期任务 MD 文档机制，记录开发阶段、卡点、数据版本，可快速查询数据真假，兼作交接文档。
- C7 加载态 → 修改框架：场景加载慢底板未出，属平台问题非前端问题；方案为通用半透明 loading 面板（可看下方内容、拦截用户操作），TB 明确要求时做全遮盖方案；首屏加载态需开发。
- C8 组件复用 → 质量清单（待梳理）：跨模块复用组件首版写死间距、后续补参，现象未纳入标准文档覆盖；先梳理现象，后续对应分级要求输出结论及修订意见。

三、按标准现有维度的验证结论
1. UI 高保真还原 —— 条款可执行，但缺前置输入
- 静态视觉是标准中可执行性最好的维度。漳河已跑通"分级差异清单 + 元素锚点 + 设计值/实测值/差异量 + 可执行复测断言"的程序化验收闭环，把"还原度＞95%"变成了可回归的断言。
- 但四个项目均无设计侧交付的字体/字号/字重规格表与色值表，真值只能由开发从设计图墨迹和切片反推 —— 此时 4.1 的「字体规范」「色彩体系」两行不可客观判定，判定结果也不可复现。
- 高频技术坑（建议写入规范附录）：渐变描边与圆角的实现方式互斥；全局标签级样式劫持新增元素。
反馈：4.1 条款本身不改，但必须配套「设计交付物完整性」前置条件，否则条款失去判定基础。
2.  3D 场景 —— 最大质量风险区，颗粒度严重不足
- 现行三行（镜头视角 / 光照效果 / 场景功能）描述的是"配了什么"，而实际质量成本在"配完之后行为是否一致"：镜头抢占、状态互斥、加载时序、离页复位、接口静默失败，全部无条款。
- 光照在四个项目中基本沿用全局，其条款优先级明显低于在文档中的篇幅占比；而镜头的真实工作量不在"配几个位姿"，而在位姿冲突治理。
反馈：4.4 必须从「配置导向」改为「行为一致性导向」，并拆细子维度（见建议一）。
3. 前端动效与交互反馈 —— 基本达标，缺两条约束
- 进场动画、模块动画、hover/激活反馈四个项目均已达成。
- 缺口：① 加载态未反映真实完成度（提前收起、不含全部资源、进度回退）；② 只要求"带过渡动画"，未约束新旧交叠不得出现空白帧。

建议六【P2】新增「附录：平台能力下沉清单」
以下能力已被 2 个及以上项目重复实现，应下沉为二开脚手架默认能力，而非每个项目各自重写：

- 场景操作串行化 + 交互防抖
- 统一镜头入口（同位姿去重 + 指令令牌 + 手动操作使缓存失效）
- 场景就绪回调幂等清理

会议备注（2026-09-10 录音）：
- 推流恢复兜底：确认写入框架，自动重连 5 秒一次，含失败监听，覆盖所有项目（各项目都要，不是可选项）。
- 交互防抖：无法统一纳入框架，属需人工设计的状态管理行为，AI 不能代设计；划为 L3 级单独设计项。
- 统一镜头入口：作为开发规范在开发阶段统一落地，不写入质量文档。
- 场景就绪回调幂等清理：无需额外做，UI 一次提供全部组件后通过参数对接即可。
- 跨模块复用组件默认暴露核心样式参数：现象未覆盖标准，先梳理，后续按分级输出结论。
分类：推流重连、全局 loading → 修改框架；交互防抖 → 质量清单（L3）；统一镜头入口 → 开发规范；场景就绪清理 → 不做。

五、结论
四个项目的实践共同指向一个判断：现行标准在"静态视觉"上基本够用，在"动态行为"上几乎空白。
标准的篇幅分配与实际质量成本分布存在明显错位 —— UI 与适配占了大部分条款，但返工第一大源是 3D 场景交互与状态时序，对应条款仅三行。同时，标准缺少「质量前置条件」与「验收证据」两个支撑章节，导致主观条款不可判定、判定结果不可复现、输入缺口被误计为执行问题。

本总结随新项目交付持续更新；新暴露的质量问题按"现象 / 根因 / 共性场景 / 标准反馈"四段式追加。

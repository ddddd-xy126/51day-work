## 二、核心结论（先行）

1. **返工第一大源是 3D 场景交互，而标准 4.4 只有三行条款。** 嘉兴 4 个 3D 交互模块合计改动 108 次（全项目第一）；漳河 3D 相关交互占全部开发交互的 23%，且返工 90% 落在 4.4 三行条款**都没有描述**的地方（状态互斥、加载时序、接口契约）。**标准对最大风险区的覆盖度最低。**
2. **多数返工不是"做得不好"，而是"输入不完整只能先猜后改"。** 四个项目共同缺失：字体/字号规格表、场景接口契约版本、3D 坐标高度基准、目标分辨率清单。标准没有"质量前置条件"章节，导致输入缺口被计为执行问题。
3. **标准的主观条款不可复测。** "还原度＞95%""色值精准匹配"在没有设计规格表与验收证据要求时，判定结果无法复现，也无法回归。
4. **存在整章级空白：数据有效性、安全、验收证据、工程过程规范**，四个项目均有实际问题命中，标准均无对应条款。
5. **大量问题在设计稿基准分辨率下 100% 不可见**（尺寸二次放大、3D 内像素资产不缩放、亚像素细线消失、推流卡死），属于典型"验收漏网场景"，必须靠强制的非基准分辨率回归拦截。

## 四、按标准现有维度的验证结论

### 4.1 UI 高保真还原 —— **条款可执行，但缺前置输入**

- 静态视觉是标准中**可执行性最好**的维度。漳河已跑通"分级差异清单 + 元素锚点 + 设计值/实测值/差异量 + 可执行复测断言"的程序化验收闭环，把"还原度＞95%"变成了可回归的断言。
- 但四个项目均无设计侧交付的**字体/字号/字重规格表与色值表**，真值只能由开发从设计图墨迹和切片反推 —— 此时 4.1 的「字体规范」「色彩体系」两行**不可客观判定，判定结果也不可复现**。
- 高频技术坑（建议写入规范附录）：渐变描边与圆角的实现方式互斥；全局标签级样式劫持新增元素。

**反馈：4.1 条款本身不改，但必须配套「设计交付物完整性」前置条件，否则条款失去判定基础。**

### 4.2 屏幕适配 —— **2D 达标，3D 侧是盲区**

- 弹性布局方案四个项目均已落地，2D 侧问题不大。
- **完全未覆盖的两类**：① 3D 场景内以像素为单位的资产（标记、标签、场景内弹窗、字号、偏移）在多分辨率下的一致性，以及米制单位参数不得参与像素缩放；② 装饰性细线缩放后低于 1 物理像素而消失。
- 这两类 + 尺寸二次放大 + 推流卡死，共同特征都是**在设计稿基准分辨率下必然漏检**。

**反馈：4.2 需补 3D 侧判据、1 物理像素保底，并强制非基准分辨率回归。**

### 4.4 3D 场景 —— **最大质量风险区，颗粒度严重不足**

- 现行三行（镜头视角 / 光照效果 / 场景功能）描述的是"配了什么"，而实际质量成本在"**配完之后行为是否一致**"：镜头抢占、状态互斥、加载时序、离页复位、接口静默失败，全部无条款。
- 光照在四个项目中基本沿用全局，其条款优先级明显低于在文档中的篇幅占比；而镜头的真实工作量不在"配几个位姿"，而在**位姿冲突治理**。

**反馈：4.4 必须从「配置导向」改为「行为一致性导向」，并拆细子维度（见建议一）。**

### 4.6 前端动效与交互反馈 —— **基本达标，缺两条约束**

- 进场动画、模块动画、hover/激活反馈四个项目均已达成。
- 缺口：① 加载态未反映真实完成度（提前收起、不含全部资源、进度回退）；② 只要求"带过渡动画"，未约束新旧交叠不得出现空白帧。

## 五、对《二开质量标准文档》的修订建议（合并去重，按优先级）

### 建议一【P0】4.4 场景维度由 3 行拆为 6 行

| 子维度 | L1 | L2 | L3 |
|---|---|---|---|
| 镜头视角 | 需求约定的默认固定镜头 | 模块化功能级镜头 | 分模块专属镜头 |
| **镜头行为一致性（新增）** | 不做要求 | 同一交互只下发一条镜头指令；跨页/跨功能切换无抢占、无回弹；用户手动操作后状态可恢复；模型朝向与跟随/静态镜头参数取自集中基线配置 | 增加镜头运动曲线与时长按场景分级调优 |
| **场景状态互斥（新增）** | 不做要求 | 页面内所有场景功能（工具、图层、测点、弹窗）互斥关系明确且两两可枚举；快速连续点击（≥3 次/秒）无残留弹窗、无镜头抖动、无实体叠加；离页完全复位无残留 | 状态机文档化，任意路径切换均收敛 |
| **资源加载时序（新增）** | 允许进入后现加载 | 依赖地形/流式资源的实体必须在镜头落位后创建；场景就绪/预热/重连回调幂等，重复触发不叠加实体；加载进度须覆盖全部首屏资源；快速切页不残留实体 | 预加载 + 只切显隐，切换零等待 |
| 光照效果 | 全局光照 | 按业务模块配置 | 每镜头专属光照 |
| 场景功能 | 标准接口 | 标准 + 少量定制接口；**每个场景功能点须做一次负向验证**（确认关闭/清理路径同样生效） | 定制 UE To Web 架构 |

### 建议二【P0】新增「4.7 交付前置输入清单」

立项/开发启动前须齐备，缺失项显式记录为风险并对相应条款降级验收：

- [ ] 明确交付等级 L1 / L2 / L3（四个项目均缺失）
- [ ] 设计交付物：设计稿（含标注）+ 字体/字号/字重规格表 + 切图 + 色值表
- [ ] 场景接口契约：**版本号明确**的接口文档，含参数枚举合法值、回调事件名、失败返回语义
- [ ] 3D 真值：镜头位姿、点位坐标（明确是绝对海拔还是相对地表高度）、模型/特效标识映射表
- [ ] 目标分辨率清单（至少 2 个，含设计稿基准之外的分辨率）与目标硬件机型
- [ ] 组件复用范围：视觉元素被几个模块复用、哪些样式维度存在差异
- [ ] 功能互斥/联动矩阵（作为需求表固定字段）

### 建议三【P0】4.2 补充三条判据

1. 3D 场景内像素单位资产（标记、标签、场景内弹窗、字号、偏移）须与 2D 面板同比缩放；**米制单位参数（路径宽度、围墙高度等）不得参与像素缩放**。
2. 装饰性细线/虚线在任意缩放比下保证至少 1 物理像素。
3. 验收须在**非设计稿基准分辨率**下复核一次；尺寸/弹窗类功能须在 2 倍分辨率下重复触发，验证无二次放大。

### 建议四【P1】新增「4.8 验收证据要求」

| 等级 | 证据要求 |
|---|---|
| L1 | 关键页面截图 |
| L2 | 差异清单（分级 + 元素锚点 + 设计值/实测值/差异量）+ **可执行复测断言** + 至少 2 个分辨率截图 + 关键容器实测记录 |
| L3 | 在 L2 基础上增加 3D 交互路径遍历记录（含互斥矩阵与离页复位核对） |

配套判据量化：布局"无截断/无滚动条"由目视改为容器可滚动高度与可视高度相等的客观判据；关闭弹窗后文档无横向溢出。

### 建议五【P1】新增「4.9 数据有效性」

- 逐页逐面板标注数据来源（接口 / 默认数据），交付前在关闭 Mock 的状态下回归一遍。
- 每类动态实体应有一份可开关的自验证数据，保证后端未就绪时前端仍能自检。
- 接口失败须有兜底，且在界面上明确标注为兜底来源。
- 数据接口文档只含路径/方法/请求参数/响应字段，不含前端函数名、组件名等实现细节（保证跨项目可移植）。

### 建议六【P1】新增「4.10 安全与工程基线」

- 密钥/凭据不落前端可读文件与仓库，一律通过开发代理 + 环境变量注入；交付前做敏感信息全仓扫描。
- 外部来源/模型返回的文本不得以富文本方式直接渲染。
- 提交前控制台 0 Error / 0 Warning；死代码清理（核对导出是否被真实引用）。
- 提交信息规范（类型 + 简述），保证问题可回溯。

### 建议七【P2】4.6 补充两条

- **加载态真实性**：进度必须反映真实完成度，不得在资源未就绪时收起、不得回退；公共资源作用域调整后须复核所有收起路径。
- **过渡完整性**：切换过渡不得出现新旧组件之间的空白帧。

### 建议八【P2】新增「附录：平台能力下沉清单」

以下能力已被 2 个及以上项目重复实现，应下沉为二开脚手架默认能力，而非每个项目各自重写：

- 推流恢复兜底（画面被暂停后自动恢复）
- 场景操作串行化 + 交互防抖
- 统一镜头入口（同位姿去重 + 指令令牌 + 手动操作使缓存失效）
- 场景就绪回调幂等清理
- 分辨率缩放工具（禁止改写入参配置对象，避免复用时二次放大）
- 跨模块复用组件默认暴露核心样式参数

## 六、已验证有效的实践（建议推广）

| 实践 | 价值 |
|---|---|
| 可复测 UI 验收清单（分级 + 元素锚点 + 设计值/实测值/差异量 + 复测断言） | 把主观条款变成可回归断言，复测零成本 |

| 提交门禁脚本 | 结构性问题前置拦截 |
| 动态业务态以用户裁决为准，不单凭静态设计稿一帧判定 | 避免误删有效业务信息 |

## 七、可直接并入《项目自检 Checklist》的条目

- [ ] 立项文档已明确交付等级 L1/L2/L3，前置输入清单齐备（缺失项已记为风险）
- [ ] 在 ≠ 设计稿基准的分辨率下回归一次；2 倍分辨率重复触发同一弹窗，尺寸无二次放大
- [ ] 目标大屏机型首访后点击场景实体，画面不冻结、弹窗不黑屏
- [ ] 主路径整链路走查：显式测试互斥/联动矩阵中列出的**每一个组合**，而非只走一遍主路径
- [ ] 快速连续点击（≥3 次/秒）任意可切换面板/实体：无残留弹窗、无镜头抖动、无实体叠加
- [ ] 预热/重连/快速切页后重新进入，无实体重复叠加、无跨页残留
- [ ] 加载进度覆盖全部首屏资源，不提前收起、不回退
- [ ] 动态实体高度基准已确认，移动全程静止与运动高度一致

## 八、结论

四个项目的实践共同指向一个判断：**现行标准在"静态视觉"上基本够用，在"动态行为"上几乎空白。**

标准的篇幅分配与实际质量成本分布存在明显错位 —— UI 与适配占了大部分条款，但返工第一大源是 3D 场景交互与状态时序，对应条款仅三行。同时，标准缺少「质量前置条件」与「验收证据」两个支撑章节，导致主观条款不可判定、判定结果不可复现、输入缺口被误计为执行问题。

建议按 P0（4.4 拆细、4.7 前置输入、4.2 补判据）→ P1（4.8 证据、4.9 数据、4.10 安全）→ P2（4.6 补充、能力下沉）三批修订，并同步在需求表模板中增加「交付等级」「组件复用范围」「功能互斥/联动矩阵」三个字段，从源头拦截跨项目重复发生的返工。

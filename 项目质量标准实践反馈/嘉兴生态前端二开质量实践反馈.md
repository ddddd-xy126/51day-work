## 二、共性质量场景（按 Checklist 五维度归类）

每条给出：**现象 → 根因 → 复现条件 → 自检动作**，可直接补进团队 Checklist。

### 维度 1｜硬件兼容性

**场景 1.1　高分辨率下弹窗/尺寸二次放大**
- 现象：设计稿分辨率（1920）下正常，4K（3840）下第二次弹出的窗口尺寸翻倍变大。
- 根因：`countSize` 类按比例放大函数直接改写入参对象属性（`config.size = [countSize(config.size[0])...]`），配置对象被多个 POI 循环复用，第二次在已放大的值上再乘一次。
- 复现：把 DevTools/浏览器切到 2 倍分辨率，重复触发同一弹窗。
- 自检：**必须在非 1920 分辨率下回归至少一次**；比例=1 时永远看不出这个 bug。

**场景 1.2　推流在高分辨率下"卡死"在最后一帧**
- 现象：点击 POI / 清场 / 聚焦后 3D 画面冻结，所有 API 返回 success，无报错。
- 根因：WDP 库在重协商流时主动 `video.pause()` 但不自动 `.play()`，4K 弱解码硬件恢复慢到看似卡死（对应提交「延时删除弹窗，降低卡死的概率」）。
- 自检：**首访 + 4K + 大屏机器**必测；诊断只需读 `#streamingVideo` 的 `paused/currentTime`。

**场景 1.3　3D 兼容适配**（提交中 5 次「适配」、1 次「兼容」、1 次「3D兼容适配」）
- 自检：交付机型与开发机 GPU/分辨率不一致时，3D 效果需在目标机上单独回归，不能只在开发机验收。

### 维度 2｜UI 高保真还原

**场景 2.1　整列高度不严丝合缝 / 面板内容溢出被截断**
- 现象：一列若干块 + gap 有 1~3px 舍入误差，出现细滚动条或数据被截断，肉眼截图看不出。
- 根因：`flex-basis` 用百分比有舍入误差；`flex:1`(basis:0%) 与 `flex:auto` 语义混用导致 hug 链路高度算错。
- 自检：判据只认 `scrollHeight - clientHeight`（不靠肉眼看截图）；"必须铺满"的列改 `flex:0 0 pxToRem(N)` + 末块 `flex:1 1 auto` 吃余量。

**场景 2.2　关闭弹窗后出现横向白边/页面偏移**
- 根因：面板 slide 过渡瞬间撑宽 document。
- 自检：关弹窗后检查 `documentElement.scrollWidth > clientWidth` 的瞬时来源，在布局容器裁剪动画外溢。

**场景 2.3　公共布局组件自带 overflow 导致"不该有滚动条的区域"出滚动条**
- 根因：`secBox` 等公共组件内置 `.content{flex:1;overflow:auto}` 兜底，业务要求完整展示时残留细滚动条。
- 自检：要求"完整不滚动"的区域，用 `:deep()` 局部覆盖 flex + overflow，不要改公共组件本身。

### 维度 3｜场景功能实现（返工第一大源）

**场景 3.1　面板/镜头/弹窗的互斥与联动缺失**（提交：page1互斥、page2/page4互斥）
- 现象：A 面板打开时 B 面板未收起、镜头切换互相冲突、上一状态残留。
- 自检：**按用户主路径整链路走查一遍**，重点验证"功能之间的互斥/联动"，这是内审最高频反馈。

**场景 3.2　预热/重连后 POI 重复叠加**
- 根因：场景重新初始化再次触发 ready 回调，引擎残留实体未清就重新 loadAll。
- 自检：ready 回调开头先清引擎侧残留实体，再重置 JS 加载标记。

**场景 3.3　POI 重叠 / 坐标转换错位**（提交：园区概览POI重叠问题修复、坐标转换）
- 自检：POI 加载后目视核对是否有点位重叠、图标遮挡；WGS84↔GCJ02 转换要与后端字段（x84/y84）口径一致。

**场景 3.4　模型沿路径移动贴地/穿地**
- 根因：`coordZRef:surface` 只在建模时抬地一次，手动逐帧 `SetLocation` 用原始 Z 会掉地底/悬空。
- 自检：无人机/农机等"相对地表高度"的移动，走引擎 `Bound` 贴地路径或先做地形采样换算为绝对海拔。

### 维度 4｜场景效果表现

**场景 4.1　季节/时间/天气切换效果异常**（提交：微观季节变化问题修复、菜园四季效果、漫游切天气季节切时间 等 5+ 次）
- 典型坑：`SetSkylightTime(time,...)` 的 time 必须是 `"HH:mm"` 字符串，传数字场景立即变黑。
- 自检：四季/昼夜/天气切换需逐组合回归，切换后确认无黑屏、无残留特效。

**场景 4.2　渐晕/遮罩层级错误看不见效果**
- 根因：mask 用了 `z-index:-1` 跑到 3D 场景后面；应 `mix-blend-mode:multiply` 且层级卡在"场景之上、面板之下"。

### 维度 5｜数据有效性

**场景 5.1　"走接口"与"默认 mock 数据"混淆**（本项目会话高频追问）
- 现象：分不清哪些 POI/面板是真实接口、哪些是写死 mock，交付时误把 mock 当真数据。
- 自检：**逐页逐面板标注数据来源（接口路径 / 默认数据）**，Mock 关闭后回归一遍，确认接口失败有兜底且明确标注来源。

**场景 5.2　动态加载静态资源 `undefined.ext` 报错**
- 根因：直接拼 `require(@/assets/.../${name}.ext)`，name 为空时崩。
- 自检：先判空 + `keys()` 存在性校验 + 默认兜底。

### 附加维度｜安全与工程规范（建议新增进 Checklist）

**场景 A.1　密钥/凭据落盘**（本项目会话中用户主动问"要不要把后端密码写进文档"）
- 铁律：后端密码、LLM API Key 绝不写进会被复制传播的文档或前端代码；密钥走 devServer 代理注入 `.env.local`（已 gitignore），前端只调相对路径。

**场景 A.2　LLM 返回文本 XSS**
- 铁律：模型返回文本绝不 `v-html`，只有代码内置话术才可；接口失败降级本地话术库并标注"兜底"。

**场景 A.3　接口文档可移植性**（本项目会话连续返工 3 次）
- 现象：文档写成"某函数/某组件"，换到别的项目没人看得懂。
- 规范：接口文档只含 路径/方法/请求参数/响应字段，不含前端函数名、组件名、内部封装引用。

**场景 A.4　中文源码编码破坏**
- 铁律：严禁 PowerShell `Get-Content | -replace | Set-Content` 改写含中文源码（打成乱码致编译崩），一律用编辑器逐处替换。

## 三、对团队质量标准（Checklist）的优化建议

基于上面的量化证据，建议对现有《项目自检 Checklist》做如下补强：

1. **新增"多分辨率回归"强制项**：所有尺寸/弹窗类功能，必须在 ≠1920 的分辨率下回归一次（场景 1.1/1.2）——这类 bug 在设计稿分辨率下 100% 漏检。
2. **将"3D 交互互斥/联动走查"提升为独立检查段**：数据显示它是返工第一大源（4 个 wdpapi.js 改 108 次、多次互斥/镜头修复），当前 Checklist 若只有"功能实现"一条粒度过粗。
3. **新增"数据来源标注"验收项**：交付前逐面板确认 接口 / mock，并在 Mock 关闭态回归（场景 5.1）。
4. **新增独立"安全项"分段**：密钥落盘、LLM 文本 XSS、接口文档去实现细节（场景 A.1~A.3）——当前 Checklist 五维度未覆盖安全。
5. **判据量化化**：把"UI 无截断/无滚动条"从主观目视改为 `scrollHeight-clientHeight===0` 的客观判据（场景 2.1），避免截图漏检 1~3px。
6. **场景效果加"切换组合回归"**：四季/昼夜/天气/漫游需按组合矩阵回归（提交中该类问题反复出现 10+ 次）。

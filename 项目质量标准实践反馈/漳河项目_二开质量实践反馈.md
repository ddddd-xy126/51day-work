---

## 1. 反馈结论摘要

1. **标准的「静态视觉维度」可执行性最好**，UI 还原、屏幕适配两个维度按现有条款基本能判定合格与否，且已跑通"程序化验收"闭环。
2. **标准的「3D 场景维度」条款颗粒度严重不足**，是本项目质量风险的最大来源：占全部开发交互的约 23%，且返工均发生在标准条款未覆盖的地方（状态互斥、加载时序、接口契约）。
3. **标准缺少"质量前置条件"约定**（设计交付物完整性、场景接口契约版本、3D 资产坐标真值），导致大量返工不是"做得不好"，而是"输入不完整只能先猜后改"。
4. 建议在标准中新增 **4.4 的三个子维度**、**4.7 交付前置输入清单**、**4.8 可复测验收证据要求** 三处修订（详见第 5 章）。

## 3. 分维度实践验证

### 3.1 UI 高保真还原（标准 4.1）— **达标，条款可执行**

**实践做法**
- 面板皮肤统一走 `_functions.scss` 的 `@mixin panel-skin`，切图使用**九宫格 `border-image`**，避免整图拉伸导致 1px 白色顶边压成 0.28px、14px 圆角压成扁椭圆。
- 字号 token 由设计稿墨迹实测标定并写入仓库约定（Header 时间 50 / 工具栏 40 / Box 标题 36 / 正文 28 …）。
- 从设计稿反推几何用 PowerShell + System.Drawing 扫描亮度突变行列，比目测精确。

**发现的问题（标准未覆盖）**

| 问题 | 表现 | 根因 |
|---|---|---|
| **"圆角不生效"跨 3 个会话重复出现 4 次** | 渐变描边面板圆角失效 | `border-image` 会完全接管边框渲染，与 `border-radius` **规范级互斥**；双层 background（`grad-fill padding-box + grad-border border-box`）在半透明填充下会整片透出描边色 |
| 全局样式意外命中 | 新建 `<span>` 颜色被全局规则劫持 | `main.scss` 存在全局 `span{color:var(--color-primary)}`，直接命中规则优先于继承 |
| 字体规格无权威真值 | 验收文档明确记录"**无权威规格文档，文字与图形真值来自设计图墨迹和切片**" | 设计侧未交付字体/字重规格表 |

**反馈**：标准 4.1 的"色值精准匹配""字体字重还原"在**没有设计规格表**时不可客观判定，只能靠开发反推，判定结果不可复现。**这是标准的前置输入缺口，不是执行问题。**

---

### 3.2 屏幕适配（标准 4.2）— **基本达标，但 3D 侧存在盲区**

**实践做法**：`html{font-size:0.4167vw}` + `pxToRem` 与 3840 设计稿 1:1；`countFontsize.js` uiWidth=3840。

**发现的问题**

| 问题 | 表现 | 根因 / 修复 |
|---|---|---|
| 亚像素细线消失 | 1920 下 `pxToRem(1)` = 0.5px，抗锯齿后细线/虚线几乎不可见 | 保底可见性场景一律 `height: max(1px, #{pxToRem(1)})` |
| **3D 场景内像素资产未同比缩放** | 4K 下 POI 标签位置、字号全偏 | `countSize` 只缩放了 `markerSize`，`labelBgSize/labelContentOffset/textBoxWidth/字号` 全漏；而 Path 的 `width`、Range 的 `height` 是**米**，绝不能过 `countSize` |
| **同一 config 对象被复用导致尺寸翻倍** | 3840 下第二次弹窗尺寸翻倍，1920 下完全看不出 | `countSize` 直接改写入参对象属性，循环复用同一引用时二次放大 |
| flex 链路高度塌陷 | 内容溢出压到下方区块 | `flex:1` 的 `flex-basis:0%` 在 hug 链路里恒为 0 |

**反馈**：标准 4.2 只写了"无黑边、无拉伸、无布局错乱"，**完全没有覆盖 3D 场景内以像素为单位的资产（POI 标记/标签/场景内弹窗）在多分辨率下的一致性**，也没有"1 物理像素保底"要求。而这两类问题的共同特征是：**在设计稿基准分辨率（缩放比=1）下 100% 不可见**，只有换分辨率才暴露，属于典型的"验收漏网场景"。

### 3.3 3D 场景（标准 4.4）— **最大质量风险区，条款颗粒度严重不足**

现行标准 4.4 只有"镜头视角 / 光照效果 / 场景功能"三行。本项目实际发生的返工，**90% 落在这三行都没描述的地方**：

#### (1) 场景状态机与功能互斥 —— 标准完全空白

- page_3 右侧「水晶体 / 坝体剖切 / 断面剖切 + 全部测点开关 + 测点列表」需**两两互斥**，任一功能激活必须独占场景（删弹窗、隐测点、屏蔽其它 watcher 的镜头副作用）。
- **镜头抢占**是重复出现的顽疾，已定位三类根因：
  1. `Promise.all` 中显隐指令排在镜头指令之前 → 镜头起飞首帧卡顿，低海拔类别切换肉眼可见抖动；
  2. `beforeRouteLeave` 里的"清理型 commit"会异步触发本页自己的业务 watcher，watcher 里又调 `setCameraPose`，与新页面的镜头指令并发；
  3. 引擎侧接口自带隐式镜头副作用（如 `ChangeCamera`），与前端 `setCameraPose` 叠加 → "往前一下又往后"。
- 最终方案：统一镜头入口 `flyCamera` + 同位姿去重 + 序号令牌 + 用户手动操作使缓存失效。

> **共性场景（建议写入标准）**：*凡是"离页清理 / 状态复位"会写 store，都必须反查该 state 是否有本页 watcher 且 watcher 内含场景副作用（镜头、显隐、着色）；有则必须加"已关闭"早退出。*

#### (2) 资源加载与首屏时序 —— 标准完全空白

- **地形流式加载导致 POI 贴地失败**：`coordZRef:"surface"` 只在 `Scene.Create` 那一刻采样一次地形高度。首次落地 page_1 时相机还在默认位、目标区地形未加载完 → 点位悬空/陷地；从其它页切过来则正常。修复：POI 改为按分类懒建，**先飞镜头 → 等落位 + 地形加载 → 再建 POI**。
- **快速切页残留实体**：等镜头落位的 2s 挂起链在离页后恢复执行，把上一页的测点/POI 重新建到新页面。修复：每个 `await` 之后复查关闭标志；RPC 已在飞的用 `deleteObjs` 按实体删，**绝不能 `deleteTypes` 按类型删**（会误删新页面实体）。
- **loading 进度不真实**：进度条只反映引擎场景加载，不含图层加载；公共资源从"页面级"下沉为"场景级"后，收起条件又漏掉了"无页面接管"的默认路径，导致 loading 提前消失。
- **GeoLayer 请求超时**：SDK 默认接口超时仅 10s，引擎需自行下载 shp 四件套再解析，且**串行处理**；`Promise.all` 并发提交会让后几个排队至超时。修复：`SetTimeoutTime(120000)` + 串行创建。

#### (3) 平台接口契约与文档 —— 标准完全空白

- **接口 spec 存在两个版本**（`漳河接口.md` / `漳河接口2.md`），水晶体接口拆分、剖切接口参数、新增侵润线接口均不一致，按旧版实现后整体返工。
- **大量关键枚举官方文档未列全，只能反编译 SDK 校验器确认**：
  - `CameraControl.Around` 只接受 `{direction, velocity}`，传 `angle`/`distance` 直接 throw，且官方 camera 文档根本没写这个 API；
  - `pathStyle.type` 无 `flow` 值（项目老注释是错的），`rangeStyle.type/fillAreaType` 官方未列全；
  - `App.DataModel.Geometry` 路径写成 `App.Geometry` 会 undefined。
- **失败静默**是最大排查成本来源：非法枚举 / GeoLayer 配置多套一层 `configs` / 几何类型选错时，接口返回 `success:false` 且 `message` 为空，**场景什么都不出现、控制台不报错**。

> **共性场景（建议写入标准）**：*二开项目必须在开发前确认"平台接口契约版本 + 枚举真值来源"，并将"引擎侧静默失败"列为必测项。*

#### (4) 关于镜头/光照条款本身

标准 4.4 要求 L2「按业务模块配置光照」。本项目实际以镜头定制为主，光照沿用全局；而**镜头的真实工作量并不在"配几个位姿"，而在位姿的冲突治理**。建议条款从"配置"导向改为"行为一致性"导向。

### 3.4 前端动效与交互反馈（标准 4.6）— **基本达标，缺"加载态真实性"条款**

**已达成**：Box 逐个滑入、面板切换过渡（只定义 leave、脱离文档流避免挤压）、按钮 hover/激活态、场景图例与工具条状态反馈。

**发现的问题**
- 面板切换"生硬 + 闪一下"根因是旧组件被直接销毁（无 leave 动画）+ 新组件 `delayTime` 造成空白窗口 —— 属于**过渡实现方式**问题，标准只说"带过渡动画"，未约束"新旧交叠不得出现空白帧"。
- 多处 loading / 进度条问题（提前消失、不含图层加载、进度回退）本质是**加载态没有反映真实完成度**，标准 4.6 未涉及。

| 实践 | 说明 | 价值 |

## 5. 对《二开质量标准文档》的修订建议

### 建议一：4.4 场景维度拆细为 6 个子维度（**最高优先级**）

| 子维度 | L1 | L2 | L3 |
|---|---|---|---|
| 镜头视角 | 需求约定的默认固定镜头 | 模块化功能级镜头 | 分模块专属镜头 |
| **镜头行为一致性（新增）** | 不做要求 | 同一交互只下发一条镜头指令；跨页/跨功能切换无抢占、无回弹；用户手动操作后状态可恢复 | 增加镜头运动曲线与时长按场景分级调优 |
| **场景状态互斥（新增）** | 不做要求 | 页面内所有场景功能（工具、图层、测点、弹窗）互斥关系明确且**两两可枚举**，离页必须完全复位、无实体残留 | 状态机文档化，支持任意路径切换均收敛 |
| **资源加载时序（新增）** | 允许进入后现加载 | 依赖地形/流式资源的实体必须在镜头落位后创建；加载进度条须覆盖**全部**首屏资源；快速切页不得残留实体 | 预加载 + 只切显隐，切换零等待 |
| 光照效果 | 全局光照 | 按业务模块配置 | 每镜头专属光照 |
| 场景功能 | 标准接口 | 标准 + 少量定制接口 | 定制 UE To Web 架构 |

### 建议二：新增「4.7 交付前置输入清单」（质量前置条件）

立项/开发启动前必须齐备，缺失项须显式记录为风险并降级验收：

- [ ] 设计交付物：设计稿（含标注）+ **字体/字号/字重规格表** + 切图 + 色值表（缺失时 4.1 的"字体规范/色彩体系"条款不可判定）
- [ ] 场景接口契约：**版本号明确**的接口文档，含参数枚举合法值、回调事件名、失败返回语义
- [ ] 3D 真值：镜头位姿、POI 坐标（明确是绝对海拔还是相对地表高）、模型/特效 EID 映射表
- [ ] 目标分辨率清单（至少 2 个，含设计稿基准之外的分辨率）
- [ ] 明确交付等级 L1/L2/L3

### 建议三：新增「4.8 验收证据要求」

| 等级 | 证据要求 |
|---|---|
| L1 | 关键页面截图 |
| L2 | 差异清单（分级 + DOM 锚点 + 设计值/实测值/差异量）+ **可执行复测断言** + 至少 2 个分辨率截图 |
| L3 | 在 L2 基础上增加 3D 场景交互路径遍历记录（含互斥矩阵与离页复位核对） |

### 建议四：4.2 屏幕适配补充两条判据

1. **3D 场景内像素单位资产**（POI 标记、标签、场景内弹窗、字号、偏移）必须与 2D 面板同比缩放，验收须在**非设计稿基准分辨率**下复核；米制单位参数（路径宽度、围墙高度）不得参与像素缩放。
2. 装饰性细线/虚线须保证**任意缩放比下至少 1 物理像素**。

### 建议五：4.6 补充「加载态真实性」

进度条/loading 必须反映**真实完成度**：不得在资源未就绪时收起，不得回退；公共资源从页面级下沉为全局级后须复核所有收起路径。

### 建议六：新增「静默失败必测项」

二开平台接口大量存在"返回成功但场景无效果"或"返回失败但 message 为空"的情况。建议 L2 起要求：**每个场景功能点在联调阶段须有一次"负向验证"**（确认关闭/清理路径同样生效），避免上线后才发现只有单向可用。
